# 架构决策与硬约束

## ADR-001：保持模块化单体

决定：继续使用一个 Spring Boot 后端和一个 Vue 前端，按业务域分包。

原因：当前团队和用户规模约 500 人，单体更容易保证事务一致性、权限复用和运维。
微服务会提前引入分布式事务、服务发现、链路追踪和部署复杂度。

例外条件：出现明确团队边界、独立扩缩容瓶颈或发布节奏冲突，再做证据驱动拆分。

## ADR-002：PostgreSQL 任务队列优先

决定：文档 ETL 使用 `background_job` + `FOR UPDATE SKIP LOCKED` + 租约 + 退避 +
死信。Excel 导出使用专用线程池。

原因：当前任务量与基础设施复杂度不需要 RabbitMQ；数据库队列允许任务行与业务行
同事务提交，天然减少“业务提交但消息丢失”的双写问题。

约束：

- 队列是 at-least-once，消费端必须幂等。
- Worker 崩溃后靠租约接管。
- 死信必须可见、可诊断、可人工复活。
- 不能因为类名里有 Queue 就把所有异步任务无脑迁入。

## ADR-003：pgvector + Elasticsearch 双路召回

决定：同时保留语义检索和关键词检索，用 RRF 融合。

原因：制度编号、金额、专有名词依赖关键词；自然语言表达依赖向量。双路召回比单路
更稳。RRF 只依赖排名，不要求分数同量纲。

当前限制：RRF 常数为 `k=0`；最终排序没有真实 Cross-Encoder reranker。

## ADR-004：本地 Embedding

决定：使用 JVM 内 bge-small-zh，512 维。

原因：离线、低延迟、无外部 API 费用、隐私边界更清晰。

代价：模型能力固定，领域适配和升级需要单独评估。

## ADR-005：权限必须在后端逐层校验

决定：群组成员资格、文档角色门槛、Excel ACL、财务角色、WebSocket 订阅权限均需
服务端复核。

原因：前端守卫、隐藏按钮和客户端传入的用户 ID 都可能被绕过。

硬约束：

- `DocumentRoleGate` 的 fail-closed 语义不得弱化。
- Excel 子资源必须回溯到所属 document 后再鉴权。
- 财务接口不得因管理员身份自动放行。
- 工具调用中的 `groupId/userId` 必须来自可信 ToolContext。

## ADR-006：当前不引入 Redis / RabbitMQ

事实：pom 中没有 Redis 和 RabbitMQ 依赖；`RedisChunkCacheService` 是本地缓存。

决定：单实例阶段继续使用 PostgreSQL、MinIO、ES 和本地缓存。

演进触发条件：

- 全局限流和跨实例缓存成为真实问题。
- Outbox 广播延迟影响协作体验。
- 数据库队列成为吞吐瓶颈。

引入前必须先审计所有本地状态：限流、缓存、在线用户、单实例锁、STOMP broker。

## ADR-007：不修改已执行 Flyway 迁移

决定：数据库变更只新增版本。

原因：Flyway 校验和与线上历史不可回写；修改旧迁移会造成不同环境 schema 漂移。

## ADR-008：文档与结构数据不混用 ID 空间

决定：RAG document ID、Excel workbook ID、sheet ID、version ID、export task ID
都必须明确资源类型，不能互相替代。

原因：ID 碰撞会导致越权或错误查询，是计划中明确列出的高风险项。

## ADR-009：失败必须可解释

决定：上传、ETL、检索、模型和导出失败都要区分：

- 用户输入错误
- 权限错误
- 资源不存在
- 临时依赖故障
- 可重试失败
- 永久失败/死信

不得只返回“失败”或让请求无限等待。

## ADR-010：文档事实与代码同步

决定：教程、注释和 AI 交接文档中的关键数字必须有代码或测试来源。

原因：项目曾出现“教程声称队列已接入，但生产仍走事件异步”的事实漂移。

流程：先追调用方，再写结论；无法确认时标注“待验证”或“演进方向”。

## 非目标

- 第一期不拆微服务。
- 不把 FastGPT/RAGFlow 整套源码并入项目。
- 不在没有业务证据时引入 Kubernetes。
- 不承诺多租户 SaaS、复杂审批流或跨云同步。
- 不把图片/视频生成作为核心产品能力。
