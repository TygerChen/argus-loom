# ZCode 交接提示词

## 1. 只读冷启动与架构核对

```text
你现在接手 F:\ChatGPT\argus-loom。

先按顺序阅读：
AGENTS.md
ai-handoff/START_HERE.md
ai-handoff/PROJECT_TRUTH.md
ai-handoff/ARCHITECTURE.md
ai-handoff/DEVELOPMENT_GUIDE.md
ai-handoff/MEMORY_EXPORT.md
ai-handoff/DECISIONS_AND_CONSTRAINTS.md

本轮不修改任何代码，只做只读核实。要求：
1. 用自己的话概括项目定位和三条核心链路。
2. 对每个核心结论给出真实文件路径和调用方。
3. 明确区分已确认事实、待验证假设、历史文档冲突。
4. 检查 ai-handoff 是否与当前代码和测试一致。
5. 输出一份后续继续开发的建议顺序。

特别注意：当前没有真实 Redis/RabbitMQ，Reranker 默认 NoOp，
文档 ETL 已使用 background_job 而不是旧事件监听器。
```

## 2. 选择一个演进任务并先做方案

```text
请从 ai-handoff/ROADMAP_AND_BACKLOG.md 中选择一个最小可交付任务。

先不要写代码。请基于当前源码输出：
1. 任务要解决的真实问题和用户价值。
2. 涉及的生产调用链、入口、服务、Mapper、表、测试。
3. 当前实现与目标实现的差距。
4. 最小改动方案，以及不采用其他方案的理由。
5. 失败路径、幂等、权限、事务、并发和回滚。
6. 测试清单和精确验证命令。
7. 预计修改的文件列表和提交边界。

如果计划里的事实与源码不一致，先纠正计划，不要顺着错误前提开发。
```

## 3. 测试先行实现

```text
按刚才确认的方案开始实现，但必须遵守：

- 先补失败测试，再写生产代码。
- 不修改 V1-V8 已执行 Flyway 迁移。
- 不绕过 DocumentRoleGate、Excel ACL、财务角色校验。
- 新增长任务必须有界、可超时、可重试、可观测。
- 不做与当前任务无关的重构。
- 每一步先运行聚焦测试，再运行全量测试。
- 如果发现文档与代码冲突，停止并向用户说明。
- 不允许为了通过测试而放宽断言或吞掉异常。

完成后报告真实改动、测试命令、测试结果、未验证项和回滚方式。
```

## 4. 代码审查模式

```text
请对当前改动做严格代码审查，优先找：
1. 越权/IDOR/缓存泄漏。
2. 事务边界和业务/任务双写不一致。
3. at-least-once 下的重复写入。
4. 无界线程、队列、内存或连接。
5. 超时、重试、死信和降级缺失。
6. 状态机无法恢复。
7. 前后端契约变化。
8. 测试只验证实现细节，没有验证真实行为。

按 P0/P1/P2 排序，给文件路径、行号、触发条件和修复建议。
如果没有发现问题，也要说明残余风险和未覆盖测试。
```

## 5. RAG 专项升级

```text
请先核实当前 RAG 管线，再提出升级方案。

必须区分：
- 已实现：查询规划、pgvector+ES 双路、RRF k=0、角色过滤、邻居窗口、证据拒答。
- 未实现：真实 reranker、HyDE、父子分块、GraphRAG、语义缓存。

本次只允许选择一个升级点。先给出：
1. 它解决什么失败类型。
2. 如何建立基线（HitRate/MRR/引用正确率/拒答正确率/延迟/成本）。
3. 失败时如何降级到现有 RRF 路径。
4. 权限和缓存隔离。
5. 是否需要数据库迁移。
6. 需要哪些真实测试集和对照实验。
```

```text
不要只根据类名判断。
```
