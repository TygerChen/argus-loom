# 必考题深挖追问集（L2/L3 追问链，2026-10-24）

用法：背熟 L1 之后，真正拉开差距的是 L2/L3。每条追问链按面试官真实思路往下钻，答案要点来自项目真实实现。**答不上 L3 时的标准动作：说清"我知道的边界 + 我会怎么查"，不编。**

## 1. SKIP LOCKED 抢单

- **L1**：多 worker 怎么保证不重复消费？→ `FOR UPDATE SKIP LOCKED`：事务 A 锁住某行时，B 的查询直接跳过该行拿下一行。
- **L2**：SKIP LOCKED 和 `SELECT ... FOR UPDATE` 普通加锁的区别？→ 普通 FOR UPDATE 会阻塞等锁，worker 互相排队浪费吞吐；SKIP LOCKED 非阻塞跳过，各拿各的，天然负载均衡。
- **L3**：两个事务同时 SKIP LOCKED 会不会有竞态？→ 不会：行锁在 PostgreSQL 是互斥的，同一行同一时刻只有一个事务能 FOR UPDATE 成功；"跳过"读的是锁的可见性，这是数据库层保证，不是应用层约定。**追问点**：既然行锁就够，为什么要租约？→ 行锁只保护"拿"的瞬间；worker 拿到后崩溃，锁随事务结束释放，任务卡在 RUNNING——租约 5 分钟超时后由恢复 Runner 重新入队。
- **挂人信号**：把 SKIP LOCKED 说成"乐观锁"或"分布式锁"。

## 2. 租约到期但 worker 还活着

- **L1**：租约 5 分钟超时后任务被重新入队，原 worker 还在跑怎么办？→ 会不会双执行？会。所以**执行体必须幂等**：先清后建（重跑先删该文档旧分片）、确定性 UUID（同一文档每次生成相同 ID 覆盖而非新增）、幂等键防同单写两遍。
- **L2**：为什么不直接"心跳续租"？→ 可以做，但要引入心跳线程和时钟漂移处理；幂等是本来就要有的正确性兜底，有了幂等，双执行只是浪费不算错误——用幂等换掉续租复杂度，量级小时是更便宜的方案。
- **L3**：先清后建在并发下安全吗？→ 同一文档并发重建被幂等键+任务状态机约束：同键任务不会被两个 worker 同时 RUNNING（SKIP LOCKED 抢单保证），所以清+建是单执行者顺序操作。

## 3. RRF 为什么 k=0

- **L1**：双路分数怎么融合？→ RRF：每路按排名给倒数分，`score = Σ 1/(k+rank)`。
- **L2**：为什么不用分数加权？→ BM25 分和余弦相似度量纲不同、分布不同，加权要先归一化且对参数敏感；RRF 只用排名不用分值，免调参、稳健。
- **L3**：k 的作用是什么？为什么这里取 0？→ k 是平滑项，防止头部排名权重过大；k=0 时 score=1/rank，头部更陡，实测对我们的 topK5 截断更友好。**关键**：这个参数是评测集上对比出来的，不是拍的。

## 4. 精排 3.47 秒太慢怎么办

- **L1**：50 对 cross-encoder 3.47s，用户等得起吗？→ 问答总预算内可接受，且有三层优化空间。
- **L2**：具体怎么优化？→ ①批量推理（50 对一个 batch）；②先截断再精排（50→20 只排头部）；③精排结果缓存；④降级链保底：本地→远程 rerank 端点→NoOp 直接用 RRF 序。
- **L3**：降级了准确率掉多少？→ 评测有数：NoOp 基线 170 例 HitRate@5 97.6%、综合 94.1%，和精排开/关的对比直接量化了"降级损失"——所以敢降。

## 5. 拒答阈值怎么定的

- **L1**：什么时候拒答？→ EvidenceAssessor 评估 topK 证据质量，不足则拒。
- **L2**：阈值怎么调出来的？→ 评测集里专门放了"知识库没有"的问题，要求拒答 100% 命中；阈值卡在"正常问题不误拒"和"无据问题必拒"的边界上，两边都有指标。
- **L3**：用户抱怨"明明有资料却拒答"怎么办？→ 这是召回问题不是阈值问题：先看该 case 的双路召回是否命中（HitRate），命中了被精排挤掉是排序问题，没命中是切片/向量化问题——归因链条清楚，改对应层，而不是全局放宽阈值。

## 6. 引用怎么保证不错位

- **L1**：引用角标和原文怎么对上？→ 分片入库时带 documentId/chunkId/位置，CitationAssembler 在生成后把回答中的引用标记映射回 chunk 记录，前端点开跳原文。
- **L2**：LLM 幻觉编了个不存在的引用编号怎么办？→ 引用映射只认证据集里真实存在的 chunk：编号超出证据集的标记在装配阶段被丢弃，不渲染假引用。
- **L3**：回答内容本身和引用 chunk 不一致呢？→ 这是防幻觉的 prompt 约束（只依据证据作答）+ 评测集抽样核对的组合；工程上做不到 100%，所以引用可回溯本身就是为了让人工抽查成本趋近于零。

## 7. JWT 双 token 设计

- **L1**：为什么双 token？→ accessToken 短命（30 分钟）降低泄露窗口，refreshToken 长命（14 天）换无感续期。
- **L2**：refresh 为什么放 HttpOnly Cookie？→ 防 XSS 偷 token；accessToken 内存持有、随请求头走，泄露面最小。登出后服务端能主动吊销 refresh——纯 JWT 吊销难，所以 refreshToken 才是吊销的抓手。
- **L3**：并发请求同时 401 怎么办？→ 前端刷新要防抖：只发一个 refresh 请求，其余请求挂起等新 token 再重放，避免多请求各自刷新导致部分用旧 token 失败。

## 8. 越权返回空证据而不是 403

- **L1**：为什么越权不报 403？→ 403 等于告诉攻击者"这个 ID 存在，换个 ID 再试"，方便枚举。
- **L2**：返回空会不会影响正常用户的错误感知？→ 会，所以正常流程里"无权"和"不存在"对用户表现一致（都像不存在），这是刻意的安全模糊；真实操作（导出/编辑）则 fail-closed 明确拒绝。
- **L3**：怎么验证防枚举有效？→ 权限测试用例覆盖"越权用户查询他人文档"，断言响应与查不存在文档完全一致。

## 9. LWW 丢更新怎么办

- **L1**：冲突合并用什么？→ LWW，最后写入赢。
- **L2**：两人同时改一个单元格，先写的会丢——能接受吗？→ 单元格粒度下，"覆盖"是用户可理解的语义（Excel 本地也一样）；关键是不丢"别人的其他单元格"。丢更新只在同格同刻发生，概率低且语义明确。
- **L3**：什么时候必须升级成 OT/CRDT？→ 当产品语义要求"合并编辑内容"（如同一段文字协同）时；表格单元格是低粒度原子值，LWW 是复杂度和体验的正确折中——能讲清"为什么不用更高级的方案"比用了更高级的方案更值钱。

## 10. 切片参数 240/320 怎么定的

- **L1**：切片目标 240 token、上限 320、重叠多少？→ 结构感知切片：按标题/段落边界切，参数是这个文档形态下的实测值。
- **L2**：为什么结构感知而不是定长切？→ 定长会把一句话切两半，检索命中半句话，证据不可读；结构感知保证每个切片语义完整，重叠防边界句丢失。
- **L3**：换了文档类型（纯文本/代码）怎么办？→ 参数进配置不进代码，换语料重跑评测集再调——参数是评测的输出，不是输入。

## 11. 1646 个测试怎么组织的

- **L1**：测试怎么跑的？→ `mvn -o test`，1646 个全绿是全量回归的结果。
- **L2**：都测什么层？→ 以服务层单测为主（mock 依赖，测业务语义和失败路径），控制器层测权限与参数校验，关键链路有集成测试；每个修过的 bug 先写失败测试再修（两个 IDOR 都是 TDD 修的）。
- **L3**：测试怎么防"改了 A 坏了 B"？→ 这正是全量回归的意义：AI 协作开发里每次改动跑全量，1646 就是防回归的安全网——没有这个网，AI 的产出速度会变成事故速度。

## 12. 生产配置防呆的实现原理

- **L1**：怎么做到"配置缺失拒绝启动"？→ 自定义 EnvironmentPostProcessor，注册在 spring.factories，早于应用上下文初始化执行。
- **L2**：为什么不用 @Value 校验或 Actuator？→ @Value 太晚——bean 初始化才发现，报错深且可能半初始化；EnvironmentPostProcessor 在环境准备阶段就拦截，报错直达"缺哪个键"。
- **L3**：校验哪些？→ prod profile 下 9 个必填键 + 拒绝值清单（默认密码类）+ JWT 密钥长度 ≥32。**追问"本地开发会不会误伤"**→ 只对 prod profile 生效，dev 不拦。
