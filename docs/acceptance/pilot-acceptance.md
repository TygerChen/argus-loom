# 试点验收手册（任务 13）

按以下场景逐项验收，全部通过即视为具备内部试点条件。
每个场景记录：执行人、日期、结果（通过/失败/阻塞）、证据（截图外用 DOM/接口响应）。

## 功能场景

1. **版本引用**：上传三份制度（含修订版本），普通员工提问，答案引用必须指向最新版本。
2. **权限反向（IDOR）**：普通员工逐一猜测财务文档、工作簿、工作表、版本、导出任务 ID，全部 403/404。
3. **协同冲突**：两名财务人员同时编辑预算表同一单元格，产生 REVISION_CONFLICT 提示，审计记录准确。
4. **导入校验**：导入含 10 条错误的费用流水，预览准确定位；修正后导入一次成功，重复上传同文件被拒（FINANCE_FILE_DUPLICATED）。
5. **期间关闭**：关闭 9 月后修改该月流水被拒（FINANCE_PERIOD_CLOSED）；重新打开必须填原因并留审计。
6. **安全回归**：XSS、私网 URL（SSRF）、压缩炸弹、超大批量协同消息，全部按 security-regression-checklist.md 通过。

## 容量与故障演练

7. **压测**：预发布环境（2 API + 1 Worker）执行 `scripts/load/` 三个 k6 脚本
   30 分钟、100 虚拟用户混合负载（70% 知识库读 / 20% 检索问答 / 10% Excel 访问），
   同时维持 20 个 WebSocket 协作连接与 5 个后台上传任务。
8. **滚动重启**：压测中重启一台 API，验证正在编辑的用户重连后可继续编辑、
   任务不重复执行（background_job 幂等 + 租约接管）、未授权资源不因缓存泄露。
