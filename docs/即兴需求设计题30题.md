# 即兴需求设计题 30 题（"现场给你加个功能，你怎么做"）

> 场景：面试官看你项目讲得好，突然出招——"如果要你给这个系统加 XX，你怎么做？"考的是**即时方案能力**，无法背诵，只能练框架。
> 每题答案结构固定（背这个框架比背答案重要）：**①澄清一句 → ②数据模型 → ③核心方案 → ④边界/权衡**。
> 每题 60-90 秒讲完，讲完主动问"这个方向您觉得 OK 吗，还是想深入某块？"

## 通用回答模板

```
① 澄清：这个功能的量级和边界？（一天多少次？谁能用？要实时吗？）
② 模型：需要什么新表/字段？和现有表什么关系？
③ 方案：核心链路怎么走？复用哪些已有组件？
④ 权衡：最简单的做法 vs 更完备的做法，当前量级选哪个？失效/边界情况？
```

---

**T1 给问答加"答案点赞/点踩"**
模型：`qa_feedback(record_id, user_id, value, reason)`，唯一索引防重复。
方案：POST 接口 + 评分聚合进问答记录表；重复点击=更新而非新增（幂等）。
权衡：实时写 DB 够用（内部系统量级）；量大转 Redis 缓冲+异步落库。
追问：为什么点踩？→ 评测数据来源！点踩样本进评测集——**这个回答把功能变成质量闭环**，全场最佳方向。

**T2 搜索结果关键词高亮**
方案：检索时拿到命中关键词（ES 的 highlight API 或查询词分词），返回给前端在前端渲染层做 `<mark>`——**后端给数据，前端做展示**，不做后端拼 HTML（转义风险）。
边界：关键词列表去重、截断（避免返回全部分词）。
追问：为什么不在后端拼好？→ XSS 转义责任在后端更容易漏，展示层职责归前端。

**T3 文档分享链接（免登录预览）**
模型：`share(token, doc_id, expire_at, created_by, revoked)`。
方案：生成随机 token（不可枚举，不是自增 ID）→ 访问路由按 token 查分享 → 绕过登录但走"只读视图"。
边界：过期/撤销即失效；分享链接的权限=文档的只读子集，**绝不透传原权限**；预览服务对 share token 单独限流（被爬）。
权衡：token 放 URL 路径（短）vs query（可撤）——路径+随机 128bit 足够。

**T4 操作日志查询页（审计）**
模型：已有 operation_log 表，加查询接口。
方案：分页 + 筛选（操作人/类型/时间范围）+ 索引（operator_id+created_at 联合索引，最左前缀）；导出复用已有 excelExportExecutor。
边界：日志只追加不改（append-only）；敏感字段脱敏后再落日志。

**T5 批量导入用户**
方案：上传 xlsx（复用解析）→ 校验（逐行：邮箱唯一/必填）→ 有效行入库、错误行生成**错误报告文件**让用户下载（行号+原因）。
权衡：同步 vs 异步——100 行内同步返回，超阈值走任务队列（复用 background_job）。
追问：导入过程一半失败怎么办？→ 事务包裹按行 or 全量回滚，业务定"全部成功或错误报告"两种模式。

**T6 文档水印**
方案：预览/导出时叠加当前用户标识（前端 canvas 水印 + 导出文件服务器端打水印）。
边界：前端水印可被 DevTools 删——**威慑不是安全边界**，真正的安全是权限+审计日志（配合 T4）。
权衡：纯前端（简单可删）vs 服务端渲染水印（可靠成本高）——按"内部威慑"定位选前者+审计兜底。

**T7 收藏夹**
模型：`favorite(user_id, doc_id, folder_id, created_at)`。
方案：唯一索引防重；列表按 created_at 倒序分页；文件夹是可选的扁平分组（不做无限层级——第一版）。
权衡：要不要文件夹？先做扁平收藏列表，文件夹是二期（MVP 思维现场演示）。

**T8 消息通知中心**
模型：`notification(id, user_id, type, payload_json, read_at, created_at)`。
方案：产生事件的地方（文档处理完成/被@/被分享）写通知表；前端轮询未读数 or SSE 推送（系统已有 SSE 基建，复用）。
权衡：轮询简单 vs SSE 实时——内部系统先轮询 30s，量级上来再切推送。

**T9 Excel 公式重新计算**
方案：Univer 前端本地算（编辑即时反馈）+ 保存时不存公式结果只存公式；服务端导出时用引擎重算。
边界：**不要尝试服务端实时算**——Excel 公式依赖图是前端强项；服务端只负责导出快照。
追问：公式依赖别的 sheet？→ 按依赖序计算或全簿重算（小表无所谓）。

**T10 协同编辑显示"谁在编辑哪个单元格"（光标共享）**
方案：STOMP 上已有编辑广播，扩展一条 cursor 消息（userId+sheet+cell）节流 200ms 发送；前端渲染彩色光标；离开房间广播离场。
边界：节流防消息风暴；断线重连后全量同步一次在线人列表。

**T11 敏感词过滤（上传/提问时）**
方案：DFA/AC 自动机词库匹配，词库可配置（管理端维护）；命中→拒绝或脱敏。
权衡：正则逐词（简单但多词性能差）vs DFA（一次扫描全匹配）；词库热更新（定时加载+版本号）。
追问：误杀怎么办？→ 白名单 + 记录命中的词，人工复核。

**T12 文档对比（版本 diff）**
方案：文本层用 diff 算法（Myers）比较两个快照的 chunk 文本；展示行级增删。结构层（表格）按 cell 对比。
权衡：字符级 diff 精细但展示噪音大，行级够用；大文档分 chunk 对比（复用切片结构）。

**T13 定时清理回收站（30 天自动清除）**
方案：复用任务队列加一个 job_type=recycle_cleanup，每日跑一次：查询过期项 → 真删除文件+索引+记录。
边界：先软删记录+文件删除要幂等（重跑不炸）；清理前告警（给管理员撤销窗口）。
挂钩：这就是"延迟任务"场景，队列加个类型就行——演示项目可扩展性的活证据。

**T14 搜索历史与热门搜索**
模型：`search_history(user_id, query, created_at)` + 热榜聚合（D10 复用）。
方案：记录落库异步化（不阻塞主查询）；个人历史去重（同 query 更新时间）；热门=滑动窗口计数。
边界：敏感查询不入历史（合规）；历史给用户自助清除入口（隐私）。

**T15 API 开放平台（第三方接入）**
方案：API Key + Secret 签名（HMAC）→ 网关校验；限流按 key（令牌桶）；只开放只读接口（文档列表/问答）。
边界：**先问开放范围**——问答接口会烧 LLM 钱，配额管理（Q16）必须先行。
权衡：签名 vs OAuth2——内部合作签名足够，开放生态才上 OAuth2。

**T16 API 配额管理**
模型：`api_quota(key_id, day, used_tokens, limit)`。
方案：调用前查配额（Redis INCR 原子累加），超额 429；日切重置。
挂钩：LLM 成本观测已落库（使用统计页），配额=成本观测的执行手段——"能看"到"能管"的一步。

**T17 Webhook（文档处理完成回调第三方）**
方案：任务 SUCCEEDED 时 POST 回调 URL（带签名），失败重试 3 次退避 → 死信。
边界：重试要幂等（对方也要防重）；回调 URL 白名单防 SSRF（内网地址黑名单）。
挂钩：**事件机制我已有 Outbox**——Webhook 就是 Outbox 的一个新消费者，讲"复用现有事件表"是本场最优解。

**T18 首次登录引导（onboarding）**
方案：前端 localStorage 标记 + 引导组件；后端零改动（或 user 表加 onboarded 字段跨设备）。
权衡：为什么问后端？——如果引导是"完成三件事"的打卡（上传一次/问一次/建一次群），需要后端统计完成度 → 复用操作日志查询。
要点：这题考的是"不要过度设计"——前端方案先答，再说何时需要后端。

**T19 全文搜索高亮排序优化（检索质量迭代）**
方案：BM25 已有 → 加"标题命中加权"（字段级 boost）+ 新鲜度因子（时间衰减）；评测集跑 A/B 对比。
**挂钩**：所有检索改动必须过评测集——"改参数前先跑 40 例基线，涨了才合"，这是质量纪律不是技术细节。

**T20 暗黑模式**
方案：纯前端（CSS 变量 + prefers-color-scheme），后端零改动；用户偏好存 localStorage（跨设备才进 user 表）。
要点：主动说"这是纯前端任务，后端唯一可能参与的是偏好持久化"——**知道自己边界**的答案。

**T21 多语言（i18n）**
方案：前端 i18n 资源文件（按语言拆 JSON）；后端错误消息码化（code + 前端映射文案），**不要后端存多语言字符串**。
边界：LLM 回答无法预翻译（动态内容）——提示词指定输出语言。
追问：语言列表怎么扩展？→ 加资源文件不改代码。

**T22 导出为 PDF**
方案：后端渲染（如 headless browser / PDF 库）复用导出任务队列（excelExportExecutor 模式：有界线程池+进度查询）；大文档分页渲染。
权衡：前端 print-to-PDF（简单不可控）vs 服务端（可控成本高）——按"需要水印和统一格式"选服务端。

**T23 在线人数与活跃度统计**
方案：心跳上报（前端 30s ping）→ Redis Set/Bitmap（分钟级在线）→ 定时聚合落库。
挂钩：BITMAP 签到（D9）同源；聚合结果进使用统计页（已有）。

**T24 权限继承（群组角色对文档的批量生效）**
方案：文档权限 = 显式授权 OR 群组角色推导；判定顺序显式 > 继承 > 默认拒绝。
边界：性能——判定链有缓存（失效：群组角色变更时批量失效）。
**挂钩**：我的三层 fail-closed 是"文档门→群组→财务"链，继承是这条链的自然扩展；强调"默认拒绝不变"。

**T25 大文件上传断点续传**
方案：分片上传已有（init/chunks/complete 三段式）——补"秒传"（文件 hash 秒判断已存在）与"断点续传"（已传分片查询接口，客户端跳过）。
边界：分片完整性校验（每片 MD5 或最终合并校验全量 hash）。
挂钩：**我的上传接口就是分片三段式**——这题等于在自己项目上做增量设计，主场。

**T26 移动端适配**
方案：响应式布局（同一套代码）为主；复杂交互（表格协同）出移动只读版——**协同编辑在手机上是伪需求，只读+轻编辑是实事求是的范围决策**。
权衡：响应式 vs 小程序/App——先响应式验证使用率。

**T27 表格支持更多函数**
方案：函数注册表（名称/参数校验/计算函数）→ 新函数=注册新条目；复杂函数（跨表引用）分批。
边界：循环引用检测（依赖图+环检测）——一句话点到，说明知道深浅。

**T28 撤销跨会话（重新打开文档还能撤销昨天的操作）**
方案：操作日志已落库（OperationLog）→ 撤销栈从"内存"升级为"按用户+文档查询日志"，undo=反向应用 delta。
边界：他人已基于你的修改继续编辑时撤销=产生新 delta（不覆盖别人）——LWW 语义下撤销也是一次普通编辑。

**T29 智能标签（自动给文档打标签）**
方案：切片时让 LLM 顺带产出 tags（JSON 字段，解析失败跳过——复用结构化输出的失败处理）；标签进 ES 字段参与检索。
权衡：单独调用 LLM 打标签（准但贵）vs 问答/切片时顺带（免费但质量略低）——选顺带，评测验证。
**挂钩**：结构化 JSON 输出+失败容忍是项目已有能力（fallbackParse），现场复用。

**T30 性能面板（给管理员看的接口耗时分布）**
方案：拦截器记录每个接口耗时 → 聚合（P50/P95/P99）落库 → 复用使用统计页展示。
边界：采样而非全量（高 QPS 下）；只记 slow（>阈值）+ 采样 normal，控制存储。
挂钩：LLM 平均延迟 17.6s 已经在统计页——把同样的观测扩展到全部接口。

## 应试心法

1. **所有题都是"复用已有组件 + 一张新表"的组合**——你的系统底座（队列/SSE/缓存/权限/任务）足够厚，这是敢即兴的底气。
2. **永远先问一句再设计**（量级/边界），哪怕你已经知道答案——这一问值印象分的 30%。
3. **主动说"第一版做多少"**——MVP 切割能力比方案华丽更打动面试官。
4. 遇到真不会的（如 WebRTC 协同音视频）：说清"我知道它解决什么问题、大概什么原理，细节我会先做最小实验"——万能话术。
