# RAG 优化路线图（评测驱动 · 面向金蝶操作手册场景）

> 前提共识：大模型幻觉不可能归零，只能靠**检索质量 + 拒答纪律 + 评测回归**压到最低。
> 原则：**每次只改一个变量，改完跑同一套评测集，用数字决定保留还是回滚。**
> 生成时间：2026-11-07。

## 一、评测基线设施（已就绪）

- 语料：金蝶官方帮助文档 40 页（`rag-opt/crawl_kingdee_help.py` 爬取，可扩到几百页）
- 评测集：`rag-opt/eval_pipeline.py` 自动生成（每篇语料 1 题 + 5 道域外拒答负例）
- 指标：HitRate@5（检索命中率）、MRR（首位命中排名）、要点覆盖率、拒答准确率、综合准确率
- 断点续跑：`eval_checkpoint.json`，中断后重跑只补缺失题
- 用法：
  ```powershell
  python eval_pipeline.py upload   # 上传语料并等 ETL READY
  python eval_pipeline.py eval     # 跑评测（当前切割参数下的基线）
  ```

## 二、实验矩阵：切割方式（第一个要跑的变量）

切割参数在 `backend/src/main/resources/application-dev.yml` 的 `ingestion.chunking`，
**改完必须重启后端，并删除旧文档重新上传**（ETL 只在上传时切一次）。

| 实验 | target/max/overlap/charsPerToken | 预期 | 适用 |
| --- | --- | --- | --- |
| A（当前基线） | 240/320/32/2 | 短块精确，长步骤可能被截断 | 问答型短手册 |
| B（代码默认） | 500/800/80/2 | 上下文更完整，噪声略增 | 步骤长、跨段落说明多的手册 |
| C（章节锁定） | 400/600/48/2 + 优先按标题边界切 | 一节一块，引用定位最准 | 强结构化 Word 手册 |

实验流程：改 yml → 重启后端 → `eval_pipeline.py upload`（先删旧文档）→ `eval` → 记录三个指标 → 对比。
评测集固定不变，只动切割参数；结果写回本文档形成趋势表。

## 四、红线（ADR-010 精神）

- 每次实验记录：参数、日期、HitRate@5/MRR/覆盖率/拒答率，**不做没有基线的优化**
- 不要把"看起来更顺"当结论，评测集会撒谎的前提是它太小或太像训练题——扩语料优先
- 拒答准确率不能拿正例换：宁可少答，不可错答（金蝶操作场景乱指一步会出生产事故）
