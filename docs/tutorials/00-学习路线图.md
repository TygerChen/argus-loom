# Argus Loom 学习路线图 —— 把这个项目真正教会你

## 这套教程是什么

这套教程**不讲语法，不讲"这个类是干嘛的"这种百科式介绍**。每一篇都围绕一个真实功能，
回答你真正会遇到的三类问题：

1. **怎么做的？** —— 带着项目真实代码，一步步走完整个流程。
2. **为什么这么做？** —— 每个设计决策都给出"别的做法 + 为什么不选它"。工程没有标准答案，只有权衡。
3. **真实世界会出什么事？面试官会怎么追问？** —— 网络断了、用户手抖点了两次、文件 2 个 GB、
   两台服务器同时处理……每一个坑都给出"不处理会怎样 → 我们怎么解决 → 30 秒面试版答案"。

特别说明：教程里的答案遵循一个产品原则——**用户体验优先，拒绝不是终点**。
失败必须告诉用户"为什么失败、能做什么"，而不是甩一句"操作失败"。
这也是面试时区分初级和有经验工程师的关键：初级会说"我做了校验"，
有经验的人会说"我让用户在犯错之前就避免犯错，犯了错也能自己恢复"。

## 看不懂术语？先读词典

教程里难免会出现一些行业"黑话"：分片、幂等、哈希、JWT、乐观锁、
SKIP LOCKED、Outbox……每个词在《00-先看这里-术语人话词典.md》里都有一个
**生活比喻 + 一句人话 + 项目里的真实落点**。建议先花 20 分钟把词典通读一遍
（当小说翻），之后读任何一篇都会顺畅十倍。读教程时卡在某个词，随时翻回去查。

## 每篇怎么用（学习法）

1. **先看"用户的故事"**，不看代码，自己想：如果是我，我会怎么做？想 5 分钟。
2. **再看设计方案**，对比你的想法。差异点就是你成长的点。
3. **逐个读 Q&A**。先遮住答案，自己答一遍，再对照。
4. **做动手实验**。教程每篇末尾有 2-3 个实验，都设计成"你自己在本地就能复现"。
   读十遍不如断一次网。

## 源码里的教学注释

整个项目的**核心类都有教学级注释**：每个注释不只说"这行代码做什么"，
更说"为什么这么设计、别的方案为什么不行、对应教程哪一篇、面试官会怎么追问"。
比如 `FinanceImportService` 的类注释讲了四条业务铁律（幂等/关账/版本/并发锁），
`ExcelSheetService` 讲了"基数 + 增量 + 压实"的 LSM 存储思想，
`JwtAuthenticationFilter` 讲了请求的第一站怎么验手环。

**推荐的深度阅读顺序**（学完教程后按此链路精读源码）：
1. 认证链：`JwtAuthenticationFilter` → `AuthService` → `RefreshTokenService`
2. 权限链：`ExcelPermissionService.permissionOf` → `DocumentAccessService` → `GroupMembershipService`
3. 上传链：`useChunkedUpload.ts` → `DocumentUploadService` → `UploadInputGuard`
4. 存储链：`ExcelParserService` → `ExcelSheetService` → `ExcelVersionService`
5. 财务链：`FinanceImportService` → `FinanceSheetResolver` → `FinanceAnalysisService`
6. 问答链：`QaController` → `HybridChunkRetrievalService` → `QaRecordPersistenceService`
