# 12 · 从零启动指南 —— 第一次亲手把项目跑起来

> 教程 00-11 讲的是"这个项目是怎么想的"；这一篇讲的是"怎么让它在你电脑上活起来"。
> **跑不起来就等于不会。** 面试官问"你开发中踩过什么坑"，只读过文档的人一定露馅。
> 全程照做，预计 30-60 分钟（取决于下载速度）。

## 一、先认识这个系统的样子

一句话：**一个前后端分离的网站**。你日常用的浏览器页面是"前端"，
处理业务逻辑的程序是"后端"，数据存在几个"基础设施"软件里：

| 组件 | 用什么 | 干什么 | 默认端口 |
| --- | --- | --- | --- |
| 后端 | Java 21 + Spring Boot | 所有业务逻辑 | 10001 |
| 前端 | Vue3 + Vite | 浏览器里的页面 | 8081 |
| 数据库 | PostgreSQL（带 pgvector 扩展） | 所有业务数据 + AI 向量 | 5432 |
| 文件仓库 | MinIO | 存上传的原始文件 | 9000 |
| 搜索引擎 | Elasticsearch | 文档关键词检索 | 9200 |

另外还有一个小助手：本地向量化服务（端口 11435，Python 脚本），帮 AI 把文字变成
向量——这是 RAG 的地基（04 篇的"给卡片做索引"）。

`scripts/start-all.ps1` 会按顺序把 Elasticsearch → MinIO → 向量化服务 → 后端 → 前端
全部拉起来，你只需要一条命令。

## 二、装软件（只装一次）

你需要在电脑上准备好：

| 软件 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | 21（推荐 Amazon Corretto 21） | Java 的运行环境 |
| Node.js | 20.19+ 或 22.12+ | 前端的运行环境 |
| PostgreSQL | 14+（**必须带 pgvector 扩展**） | 数据库 |
| Elasticsearch | 8.x | 搜索引擎 |
| MinIO | 单文件版即可 | 文件仓库 |
| Python | 3.10+ | 跑本地向量化服务 |

安装说明比教程更靠谱的是官方文档，这里只强调两个**最容易翻车的点**：

1. **PostgreSQL 必须支持 pgvector**。普通安装包没有这个扩展，向量功能直接用不了。
   Windows 上推荐用 PostGIS/官方安装器后再装 pgvector，或者直接用
   `ankane/pgvector` 的 Docker 镜像。项目启动时会执行 `CREATE EXTENSION IF NOT EXISTS vector`
   （`V1__init_core_schema.sql`），失败就说明扩展没装上。
2. **JDK 版本必须是 21**。项目用了 Java 21 的语言特性，装了 8 或 11 会编译报错。
   推荐配合 `backend/mvnw.cmd`（Maven 包装器）使用，不用单独装 Maven。

## 三、建数据库和配置

1. 在 PostgreSQL 里建库（用 pgAdmin 或命令行都行）：

   ```sql
   CREATE DATABASE argus_rag;
   ```

   不用手动建表！项目启动时会自动执行 `backend/src/main/resources/db/migration/`
   里的迁移脚本（Flyway，可以理解为"数据库的自动装修队"），表结构全自动创建。

2. 复制根目录的 `.env.example` 为 `.env`（本项目读取环境变量的"密码本"），
   至少核对这几项：

   ```ini
   POSTGRES_PASSWORD=你的数据库密码
   ARGUS_RAG_JWT_SECRET=随便一串至少32位的字符串
   MINIO_ROOT_USER=minioadmin
   MINIO_ROOT_PASSWORD=minioadmin
   OPENAI_API_KEY=local-embedding   # 本地模式不用真 Key
   ```

   **密码学第一课（面试可以讲）**：真实密码永远不写进代码仓库，
   而是放在 `.env`（本地）或系统环境变量（生产）里，代码里只写占位符
   `${POSTGRES_PASSWORD:postgres}`——冒号后是"没配置时的默认值"。
   这就是配置注入，"配置与代码分离"。

3. 打开 `backend/src/main/resources/application-local.yml` 核对地址：数据库是不是
   `localhost:5432/argus_rag`，MinIO 是不是 `localhost:9000`，ES 是不是 `localhost:9200`。
   默认值就是这些，一般不用改。

## 四、启动：一条命令（推荐）

在项目根目录的 PowerShell 里执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-all.ps1
```

脚本会自动：起 ES → 等 ES 就绪 → 起 MinIO → 等就绪 → 起向量化服务 →
起后端（10001）→ 起前端（8081）。看到"Local embedding service READY"之后
等后端日志出现启动完成即可。

**首次启动注意**：Spring Boot 第一次要下载依赖、编译全部代码，等 2-5 分钟正常；
Flyway 会自动建表；后端还会自动创建一个默认管理员（用户名 `admin`，
密码来自 `ARGUS_RAG_DEV_ADMIN_PASSWORD`，默认 `admin123`）。

## 五、验证：亲手把核心功能走一遍

浏览器打开 `http://localhost:8081`，用 admin / admin123 登录，然后：

1. **建一个知识库（群组）** → 传一个 PDF/Markdown/Excel 文档 →
   看到状态从"解析中"变成"可检索"（这就是 08 篇的异步队列在干活）；
2. 在问答页问一个**文档里有的问题** → 确认回答带引用来源（04 篇的 RAG）；
   再问一个**文档里没有的** → 确认系统拒答而不是瞎编；
3. 进 Excel 协同 → 开两个浏览器（一个普通窗口 + 一个无痕窗口，分别登录不同账号）
   编辑同一个文件 → 看修改实时同步（05 篇的 WebSocket + Outbox）；
4. 同一个文件传两次 → 第二次秒传（01 篇的哈希幂等）。

这 4 步全部走通，说明整套系统活了——**这 4 步也正是教程 01/04/05/08 篇的实验**。

## 六、起不来？按症状排查（踩坑记录式写法）

| 症状 | 大概率原因 | 怎么办 |
| --- | --- | --- |
| 启动脚本报"ES/MinIO not found" | `start-all.ps1` 顶部的路径参数指向的安装位置不存在 | 改启动命令的 `-ElasticsearchHome` / `-MinioExe` 参数，指向你的实际安装路径 |
| 后端日志大量 `Connection refused` + `postgres` | 数据库没起、密码不对、库名不对 | 先用 pgAdmin 或 `psql` 手动连一次验证 |
| 启动时 `CREATE EXTENSION vector` 报错 | PostgreSQL 没装 pgvector | 换带 pgvector 的安装方式（见第二节"最容易翻车"） |
| 前端能打开但一直转圈 | 后端没起来或端口不对 | 看 `logs/backend-*.log`；确认 10001 端口在监听 |
| 上传文件报 MinIO 错误 | MinIO 没起或桶不存在 | 打开 `http://localhost:9001`（MinIO 控制台）检查，bucket 名应为 `argus-rag-documents` |
| 问答功能报模型/网络错误 | 本地向量化服务没起（11435） | 看启动脚本是否把它拉起；手动跑 `python scripts/local-embedding-server.py` 验证 |

排查的通用三步（面试也这么答）：**看日志找第一个 ERROR → 确认"哪个组件没就绪" →
先修组件再重启**。不要看到报错就重跑，先读懂报错在说什么。

## 七、日常开发常用的命令

```powershell
# 只起后端（改了 Java 代码后）
$env:JAVA_HOME='你的JDK21路径'
cd backend; .\mvnw.cmd spring-boot:run

# 只起前端（改了 Vue 代码后，支持热更新）
cd frontend; npm run dev

# 后端全量测试（1600+ 个，全绿才算改对了）
cd backend; .\mvnw.cmd test

# 前端检查三件套
cd frontend; npm run test; npm run type-check; npm run build
```
