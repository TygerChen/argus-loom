# Argus-Loom 核心链路调用图（时序图版）

> 三条核心链路的泳道时序图，可直接粘到语雀（代码块语言选 PlantUML 即可渲染）。
> 内容与代码一致（2026-10-24 核实），配合 `backend/docs/流程架构图/` 与方法级调用图食用。

## 图 1 · 文档上传与 ETL 入库（背景任务队列）

```plantuml
@startuml
skinparam backgroundColor transparent
actor 用户
participant "浏览器" as FE
participant "后端\nDocumentController" as BE
database "PostgreSQL" as PG
participant "任务队列\nBackgroundJobWorker" as W
participant "MinIO" as S3
participant "Elasticsearch" as ES

用户 -> FE: 1. 选择文件上传
FE -> BE: 2. POST /api/documents/upload
BE -> S3: 3. 存储原始文件
BE -> PG: 4. 同事务写三张表\ndocuments(PROCESSING) + ingestion_jobs + 后台任务
note right of PG: 文档行与任务行同事务提交\n解决"业务成功但消息丢失"的双写问题\n幂等键 INGEST:{documentId}:{generation}
BE --> FE: 5. 秒回 documentId（状态=处理中）
W -> PG: 6. 每 15s 轮询领取\nSKIP LOCKED + 租约 5 分钟（多实例安全）
W -> S3: 7. 读取原始文件
W -> W: 8. 解析 → 清洗 → 结构感知切片\n（240/320 token，重叠 32）
W -> PG: 9. 先删旧 chunk 再插入（幂等）
W -> W: 10. bge-small-zh 向量化（512 维，JVM 内 ONNX）
W -> PG: 11. 向量写入 pgvector（确定性 UUID）
W -> ES: 12. chunk 写入关键词索引
W -> PG: 13. 状态置 READY
FE -> PG: 14. 前端查询看到 READY
note over W, ES: 失败路径：进程内重试 2s/4s/8s\n→ 文档置 FAILED（人话原因+重试按钮）\n→ 队列退避 1/5/15 分钟 ×3 → 死信\n→ 手动重试用新幂等代数，不撞历史
@enduml
```

## 图 2 · RAG 问答（检索 → 证据 → 生成 → 引用）

```plantuml
@startuml
skinparam backgroundColor transparent
actor 用户
participant "浏览器" as FE
participant "后端\nQaService" as BE
participant "混合检索\nHybridRetrieval" as R
database "PostgreSQL\npgvector" as PG
participant "Elasticsearch" as ES
participant "重排\nBGE reranker" as RR
participant "LLM 网关" as LLM
database "qa_records" as REC

用户 -> FE: 1. 输入问题
FE -> BE: 2. POST /api/qa/ask\n（限流 20 次/60s）
BE -> BE: 3. 群组成员校验（fail-closed）
BE -> R: 4. 检索证据
R -> R: 5. 文档角色门预过滤\n无权限=空集，防存在性探测
R -> R: 6. 查询规划\nDIRECT/REWRITE/DECOMPOSE/GLOBAL
R -> PG: 7. 向量召回 top50（HNSW）
R -> ES: 8. 关键词召回 top50（BM25）
R -> R: 9. RRF 融合(k=0) + 二次角色过滤
R -> RR: 10. BGE cross-encoder 精排\n挂了自动降级回融合原序
R -> R: 11. 证据评估分级
alt 证据不足
  BE --> FE: 12a. 明确拒答\nRETRIEVAL_NOT_GROUNDED\n（不调 LLM，不编造）
else 证据充足
  R -> R: 12b. 邻居扩展±1，topK=5
  BE -> LLM: 13. Prompt（问题+证据）生成
  LLM --> BE: 14. 回答流式返回
  BE -> REC: 15. 回答 + 引用落库
  BE --> FE: 16. SSE 事件\ntoken / citations / record
end
@enduml
```

## 图 3 · 在线 Excel 协同编辑（LWW + Outbox）

```plantuml
@startuml
skinparam backgroundColor transparent
actor 用户A
actor 用户B
participant "浏览器\nUniver" as FE
participant "STOMP\n/ws" as WS
participant "CollabService" as BE
database "PostgreSQL" as PG

用户A -> FE: 1. 编辑单元格
FE -> WS: 2. 发送 /excel/edit（带 baseRevision）
WS -> BE: 3. 消息级 canEdit 鉴权
BE -> BE: 4. LWW 时间戳仲裁\n+ revision 冲突检查
BE -> PG: 5. 写 excel_sheet_chunk_delta\n+ excel_collab_outbox(PENDING)
BE --> WS: 6. accepted(broadcast)
WS --> FE: 7. 实时直发 topic\n（同实例订阅者即时收到）
note over FE: 用户 B 收到广播：\n①直发（同实例，低延迟）\n②Outbox 每 500ms 重放（跨实例兜底）\n客户端按 requestId 去重
BE -> PG: 8. 定时快照 / 操作日志 / 块压实
用户B -> FE: 9. 看到用户 A 的编辑
@enduml
```
