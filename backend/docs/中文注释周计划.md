## 两条红线（必须死守）

1. **只加注释、绝不动代码逻辑**。目的是学习与阅读，不能顺手"修复"任何行为。尤其：
   - `ExcelPermissionService.userCanAccessDocument`
   - `DocumentRoleGate` 的权限判定逻辑
   这些是财务隔离红线，**只加注释，任何一行业务判断都不碰**。

## 第三周 · 周日补注释（2026-09-21）✅ 已完成 — 方法级注释「判别法」

**背景**：读到用户在意"是否所有该加的都加了"。跑了一次机械扫描（凡"方法上方没有紧邻 `/**`"都报），得到 **319** 个候选——但绝大多数是**自解释的 helper / getter / 工厂 / 校验**，按项目「只补真会绊倒新手、绝不为一行方法硬凑」的克制原则**不应加**（加反而是噪音）。

**判别法（以后沿用）**：

## 给你的学习顺序（新手必读）

1. **先看懂 `common/`**：`ApiResponse`、`BusinessException`、`GlobalExceptionHandler`、`ErrorCodes` —— 这是**所有接口长什么样 + 出错怎么返回**的地基。
2. **再看 `auth / user`**：搞懂"用户是谁、怎么登录"。
3. **再 `group / document / ingestion`**：搞懂"数据归谁、怎么进来、怎么切成块"。
4. **再 `excel / finance`**：主业务（在线表格 + 财务红线）。
5. **再 `qa / engine`**：这是 RAG AI 助手的大脑 ——"问 → 检索 → 拼证据 → 调模型 → 答"。
6. **最后 assistant + memory**：Agent 工具 + 短期/长期记忆。

先想象：**这周做完，你跟着"用户从登录 → 传一个 Excel → 问一句'这个月工资多少' "跑一遍全链路**，就基本把整个系统串起来了。
